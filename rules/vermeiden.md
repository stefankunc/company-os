# Vermeiden (No-Gos)

- **`npm` / `yarn`** → Immer `pnpm`.
- **`margin` für Layout-Abstände** → `gap` im Parent, `padding` oder Spacer (kein Margin-Collapse).
- **React `useEffect`-Endlosschleifen, abgeleiteter State, Mutationen & Daten-Fetching in `useEffect` + `useState`** → Abgeleitete Werte direkt im Render berechnen (nie per extra `useState` + `useEffect`); Mutationen/Nutzer-Aktionen direkt in Event-Handlern (`onClick`/`onSubmit`) auslösen (nie über State-Flags in `useEffect`); Dependency-Array minimal halten; Server-Daten via **RSC** laden, echten Client-Async-State (Polling, Live-Daten, **Expo**) mit **`@tanstack/react-query`** (verhindert Race Conditions & kaputte Loading-States).
- **`Promise.all()` für mehrere APIs/Börsen** → `Promise.allSettled()` (ein Ausfall darf nicht alles verwerfen).
- **JS für Standard-HTML** → Natives HTML (`<details>`/`<summary>`).
- **Ungetyptes JS / `any`** → Strikte TypeScript-Typen & feste Schemas.
- **HTMX + React-State mischen** → React/Next.js für Web-Apps; HTMX nur für einfache Server-/Astro-Seiten.
- **Monolithische Seiten-Komponenten** → Kleine Bausteine (`packages/ui` bzw. `apps/<App>/src/components/ui`).
- **Manuelles Formatieren** → Prettier (`pnpm format`).
- **Ganze Demo-Seiten/Repos kopieren** → Nur benötigte Komponente/Block (`rules/ui-components.md`).
- **Pauschales `"use client"` / `getServerSideProps`** → RSC-First; `"use client"` nur in kleinen Inseln.
- **Ungekapselte Fremd-SDKs, rohes `fetch()` ohne Checks & ungeprüftes JSON** → Typsichere Wrapper + **Zod**-Laufzeitvalidierung; bei `fetch()` immer `res.ok` prüfen und `AbortSignal.timeout()` setzen.
- **`SELECT *` / rohe DB-Objekte an Client** → DAL (`src/data/` + `import "server-only";`) + explizite DTOs.
- **Mutationen beim RSC-Rendern / Auth nur in Seite** → Mutationen nur in Server Actions (`"use server"` + Zod); Auth bei jedem DAL-Zugriff prüfen.
- **Rohe Third-Party-`<script>` / schwere Embeds (YouTube, Maps, GTM)** → `@next/third-parties` (Lite-Embeds / optimiertes GTM).
- **Manuelles Cloud-/DevOps-Setup (VPC, IAM, Kubernetes)** → Spezialisierte Managed-Dienste aus dem Tool Stack (`Vercel`, `Neon`/`Supabase`, `Clerk`, `UploadThing`).
- **Google Analytics (GA4) / ungeprüfte Pakete & Easter Eggs** → DSGVO-konform **Plausible** / **PostHog (EU)** nutzen (PostHog-Events nie ungeschützt im Render oder in `useEffect`-Mount-Schleifen feuern, nur bei expliziten Nutzer-Aktionen/deduplizierten Server-Events; harte Spend-Limits bei Vercel/PostHog setzen); Dependencies via `pnpm-lock.yaml` pinnen, keine winzigen Trivial-Pakete (< 100 Zeilen) installieren (kleine Helfer selbst schreiben statt Supply-Chain-Risiko) und keine Easter Eggs in Produktion.
- **Unpooled DB-Connections in Serverless / lange Tasks im HTTP-Request** → Neon-/Supabase-Pooler nutzen; rechenintensive/lange Jobs (Video-Render, KI-Pipelines) über Background-Jobs/Queues mit Retries entkoppeln.
- **Veraltete Test-/Build-Tools (`Jest`, `Enzyme`, `Webpack`)** → **Vitest** (Unit/Logik) & **Playwright** (E2E) sowie die nativen Bundler von Next.js/Astro nutzen.
- **Pauschales `useMemo` / `useCallback` / `React.memo`** → **React Compiler** (`reactCompiler: true` in Next.js) aktivieren; manuelles Memoizing nur bei gemessenem Engpass.
- **100 %-Coverage-Zwang / Mock-Unit-Tests für triviales UI & CRUD** → Pragmatisch testen: **Vitest** für komplexe Logik/Parser/DAL-Regeln, **Playwright** für kritische End-to-End-Flows.
- **Geschäftslogik/Auth in DB-Stored-Procedures, Triggern oder direktem Browser-DB-Zugriff (komplexe RLS)** → DB hält nur Daten; Auth, Regeln & Workflows liegen typsicher in TypeScript im DAL (`src/data/`) und in Server Actions.
- **Verschachtelte Ternaries, tiefe `if/else`-Ketten & `{count && ...}` in JSX** → Guard Clauses / Early Returns (`if (!x) return null`), kleine Unterkomponenten & explizite Booleans (`items.length > 0 ? ... : null`) nutzen (verhindert `0`-Rendering & React-Native-Crashes).
- **Klickbare `<div>` / Eigenbau-Modals ohne Barrierefreiheit (a11y)** → Semantisches HTML (`<button>`, `<a>`, `<label>`), `aria-label` für Icon-Buttons, `focus-visible` & barrierefreie `shadcn/ui`-Primitives nutzen.
- **Shell-Strings via `exec()` / `shell: true` mit Variablen** → `execFile()` / `spawn()` mit Argument-Array & Zod-geprüften Inputs nutzen (verhindert Command Injection & Windows-Pfad-Bugs bei Leerzeichen).
- **`@apply`-Missbrauch / semantische Custom-CSS-Klassen (`.card`, `.btn`) für UI** → Wiederverwendung über TSX-Komponenten statt CSS-Klassen; `@apply` nur als Escape Hatch für fremdes HTML-Markup (z. B. CMS/Rich-Text).
- **Große Medien in `public/` auf Vercel, offene `images.remotePatterns` & hängende Webhooks ohne `maxDuration`-Limit** → Videos, Audio, große PDFs/Bilder immer über `UploadThing`, `Mux` oder `Cloudflare R2` ausliefern (kein teurer Vercel-Egress); `images.remotePatterns` in `next.config` nie mit offenen Wildcards (`hostname: "**"`) freigeben, sondern strikt auf eigene Hosts + konkreten `pathname` (App-ID/Bucket) beschränken. Webhook-Handler (Stripe, Clerk) müssen jeden Event-Typ (auch unbehandelte) sofort mit `200 OK` quittieren und `export const maxDuration` knapp halten (z. B. `10` s).
- **Stille `catch {}`-Blöcke / verschluckte Fehler (Fail-Silent) & `console.log`-Spam** → _Fail Fast_: Unerwartete Zustände über Guard/Zod-Prüfung abbrechen und echte Fehler sauber werfen bzw. ans Error-Tracking (z. B. **Sentry**) melden – nie in leeren `try/catch`-Blöcken verstecken; in Server-Handlern keine verstreuten `console.log`-Ketten, sondern 1 strukturiertes Wide-Event (JSON mit `route`, `userId`, `durationMs`, `error`) pro Request loggen.
- **Nicht-deterministische Werte im SSR-Render (`new Date()`, `Math.random()`, `window`, lokale Zeitzonen)** → Verursacht React-Hydration-Mismatches; Zeit/Daten auf dem Server mit fester Zeitzone/Locale formatieren und als Prop übergeben oder Client-only-Werte erst nach dem Mount setzen.
- **Unbereinigtes `dangerouslySetInnerHTML` / rohes HTML aus Nutzer- oder KI-Input** → XSS- & CSS-Injection-Risiko; Standard-React-JSX nutzen und fremdes HTML/Markdown vor dem Rendern immer strikt sanitisieren (`DOMPurify` / `rehype-sanitize`).
- **TypeScript `enum` / `namespace`** → Erzeugt versteckten Laufzeit-Code und bricht natives Node.js Type-Stripping (`erasableSyntaxOnly: true` in `tsconfig.base.json`); stattdessen String-Unions (`"a" | "b"`) oder `as const`-Objekte nutzen.
- **React Context für häufig ändernden Client-State / Redux-Boilerplate** → Löst bei jeder Änderung Re-Renders aller Konsumenten aus; Server-Daten via **RSC**, Filter/Views in **URL-State** (`searchParams`), Client-Async über **`@tanstack/react-query`**; nur für echten geteilten Client-UI-State **Zustand** mit gezielten Selektoren (`useStore(s => s.field)`) nutzen.
- **Mutierbarer Modul-State / feste `/tmp`-Dateinamen in Serverless-Handlern** → Unter Vercel In-Function Concurrency teilen sich parallele Requests dieselbe Instanz (Gefahr von Cross-User-Datenlecks & Race Conditions); Handler strikt zustandslos halten (Rate-Limits/State in Redis/DB, Temp-Dateien nur mit eindeutiger ID).
- **Controlled `<TextInput value={...} />` in React Native / Expo** → Verursacht springende Cursor & verlorene Tastenanschläge bei schnellem Tippen oder blockiertem JS-Thread; **uncontrolled** mit `defaultValue` + `ref` (oder `react-hook-form` im Uncontrolled-Modus) nutzen.
- **Unlimitierte KI-Endpunkte auf eigene Kosten & vorschnelles RAG** → Bevorzugt **BYOK / Nutzer bringt eigenes KI-Abo mit**; wo eigene KI-Endpunkte laufen, über das **Vercel AI SDK** mit günstigem Standard-Modell & strikten Pro-Nutzer-Quotas/Token-Limits absichern; keine Vektor-DB/RAG-Pipeline bauen, solange Long-Context oder DB-Suche ausreicht; flache SQL-/Tabellen-Payloads für LLM-Inputs on-the-fly aus Drizzle/JSON in **TOON** encodieren (DB bleibt Postgres/Drizzle; strukturierte LLM-Outputs weiter als **JSON + Zod**).
- **Rohes `process.env.KEY!` quer im Code** → Umgebungsvariablen zentral in `src/env.ts` mit **Zod** (z. B. `@t3-oss/env-nextjs`) beim Build/Start validieren – fehlende Keys brechen den Build sofort ab statt erst in Produktion.
